# 纯轨迹方案现场操作手册

本文只描述已经成型的“完整关节轨迹 + 独立夹爪时间线”方案，不包含视觉实验。

## 1. 开机前检查

- 机械臂底座、托盘、给料位置和夹爪安装均未移动；
- CAN-H/CAN-L、电源、终端电阻正确；
- 托盘层数和任务范围与工作台一致；
- 机械臂运动范围内无人、无工具和线缆干涉；
- 急停可触达；
- 同一时刻没有第二个 Piper 控制程序运行。

## 2. 每日开机

在 Windows 工作台先执行“连接与设备检查”。树莓派侧等价命令：

```bash
cd ~/piper_robot_project
source ~/.venvs/piper_robot_project_api/bin/activate
sudo systemctl restart can0.service
ip -details -statistics link show can0
ls -l /dev/piper_gripper
python scripts/read_status.py --can-port can0
```

状态持续全零、`can0` 为 DOWN、夹爪设备不存在或机械臂有错误码时，禁止继续。

## 3. 公共给料上方点

这是各任务共用的连接锚点。机械臂、给料机构、底座或末端夹爪位置变化后必须重新录制，
并重新验证所有轨迹。

在工作台使用“录制/覆盖公共给料上方点”。录制前通过示教将机械臂放在安全、无碰撞、
可重复到达的位置。该点不是全零 Home，两者用途不同：

- 全零 Home：系统初始化和维护用程序化起点；
- 给料上方：连续生产任务之间的公共衔接点。

## 4. A：录制一个孔位的完整轨迹

1. 在工作台选择层号和孔位；
2. 确认任务名，例如 `layer_01_slot_03`；
3. 进入示教状态并确认可手动拖动；
4. 点击“A 录制机械臂完整轨迹”；
5. 从公共给料上方开始，完成取料、移动、放置、离开和返回；
6. 关键动作前后保留短暂停顿，给夹爪动作留出窗口；
7. 按 `H` 自动回到给料上方并保存；
8. 确认生成 `trajectory.csv` 和时间戳 sidecar。

录制频率默认 200 Hz。录制时的“速度百分比”不改变人工拖动速度；它主要影响程序自动
回锚点和后续回放。不要在轨迹中故意碰撞限位或依赖夹具强行纠偏。

## 5. B：回放并标注夹爪动作

1. 点击“B 回放并标注夹爪动作”；
2. 程序先到公共给料上方，不反复回全零 Home；
3. 按 `P` 暂停；
4. 在准确时刻按 `G` 闭合抓取，或按 `O` 张开放置；
5. 确认夹爪完成机械动作后按 `C` 继续；
6. 完成后保存 `gripper_timeline.json`。

夹爪事件按轨迹时间保存。生产模式默认使用机械臂实际轨迹进度触发事件，降低加速回放
造成的提前抓取问题。若改变回放倍率，仍必须重新联合验证。

## 6. C：机械臂与夹爪联合试跑

第一次必须：

- 空载或使用不会损坏设备的测试件；
- 速度 5% 到 10%；
- 回放倍率 1.0；
- 单个任务；
- 操作员手握急停。

重点观察：

- 起点是否和录制时一致；
- 夹爪闭合时物料是否已进入夹持范围；
- 夹爪张开时物料是否已到位；
- 轨迹是否擦碰托盘、料架或线缆；
- 回到给料上方时是否安全；
- 终端是否报告跟踪误差或 CAN 错误。

改变机械臂速度、回放倍率或夹爪保持时间后，必须重新执行 C。

## 7. D：拉回并保存

现场录制发生在树莓派。验证完成后点击“从树莓派拉回现场数据”，避免 Windows 下次同步
时覆盖树莓派上的新轨迹。

任务目录至少应包含：

```text
task.json
trajectory.csv
trajectory.csv.timestamps.csv
gripper_timeline.json
```

工作台会检查轨迹点数、时长和夹爪事件数量。通过后才标记为已验证。

## 8. 连续生产

完成多个单任务验证后：

1. 先选两个相邻孔位；
2. 低速连续运行；
3. 确认两个任务之间没有回全零 Home；
4. 确认 CAN 和夹爪串口只打开一次；
5. 确认第一个任务结束与第二个任务开始的给料上方段没有不必要长停顿；
6. 再逐步扩大到一排、一层和多层。

Windows 工作台的“连续生产”页支持两种循环方式：

- 填写“循环次数”：完整执行所选孔位序列指定次数；
- 勾选“无限循环”：持续执行整组任务，直到在生产终端按 `S`、`Q` 或
  `Ctrl+C` 停止。

循环只在第一次开始前前往一次给料上方。后续轮次不回全零 Home，也不重新打开
CAN 或夹爪串口。无限循环必须有人值守，并始终保证物理急停可触达。

连续生产不等于把多个独立进程依次启动。`production_stream.py` 会持续持有硬件连接，
并按任务清单流式执行，减少进程启动、串口握手和事件时序偏差。

## 9. 急停后的恢复

1. 判断并清除物理干涉；
2. 物理复位急停；
3. 检查 CAN 是否仍存在；
4. 软件恢复并重新使能；
5. 只读状态正常后，先低速运行单任务。

```bash
sudo systemctl restart can0.service
python -m teach.piper_power_control --can-port can0 --action recover
python -m teach.piper_power_control --can-port can0 --action enable --reset-first
```

若 `can0` 消失，检查 USB 和 `gs_usb`，不要反复发送运动命令。

## 10. 停机

1. 等当前任务安全结束或主动停止；
2. 张开夹爪并取走物料；
3. 回到经确认的安全位置；
4. 失能机械臂；
5. 拉回当天的新任务和日志；
6. 导出现场数据备份；
7. 再关闭机械臂和树莓派电源。

```bash
python -m teach.piper_power_control --can-port can0 --action disable
sudo shutdown -h now
```
